# Spectre V2 Cleanup Plan

**Date:** 2026-08-31
**Status:** Executed
**Goal:** Remove clutter, consolidate docs, and prepare the repo for its first GitHub push. The app works perfectly as-is; no functional changes.

## Principles

1. **Do not break the working app.** No refactoring of working code unless verification (build + tests) passes afterward.
2. **Remove one-time artifacts.** Planning docs, research notes, and raw data files that served their purpose during development.
3. **Keep the repo lean.** Regenerated assets (Cesium static files) go in `.gitignore`, not in the repo.
4. **Document what remains.** A single features reference replaces scattered spec files.

## File merges

Conservative merges only. Each merge updates all import sites and is verified by build.

| Merge | Reason |
|-------|--------|
| `src/globe/radio/radioLayer.ts` into `src/globe/radio/radio-engine.ts` | `radioLayer.ts` was an 811-byte thin shim delegating every call to `radioEngine`. The engine object already satisfies `LayerImpl`; a `radioLayer` alias export replaces the shim. Only `registry.ts` imported the shim. |

**Not merged (decided against):**
- `RightPanel.tsx` (105KB): Works perfectly. Splitting risks breaking the app for no functional gain. Left as-is.
- `src/globe/layers/types.ts` into `registry.ts`: Would create circular imports (all layer implementations import `types.ts`, and `registry.ts` imports all layer implementations). Kept separate.
- `src/lib/fetcher.ts`, `src/lib/types.ts`, `src/components/Toast.tsx`: Small but standalone utilities used across multiple modules. Merging would create coupling.
